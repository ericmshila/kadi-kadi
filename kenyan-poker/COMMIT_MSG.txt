fix: forfeit banner after restart, color-coded names, stronger hint pulse

Three fixes/enhancements from live testing feedback:

1. Fix: the Forfeit Match button stayed hidden forever for a player
   after they forfeited once, even in later rounds where they were
   back in the game. Table.tsx tracks "I voluntarily forfeited"
   client-side only (the server just knows eliminated-or-not, not
   why), and nothing ever reset it — GameRoom.restart() re-seats
   everyone with nobody eliminated, but the stale local flag kept
   canQuit false regardless. Now reset on the "game_started" event
   (fired fresh by every restart), the same event already used
   elsewhere to detect a new round.

2. Feature: player names are now color-coded — a small, deterministic
   per-player palette (playerColors.ts, hashed off the player id, so
   it's stable across reconnects and restarts) applied to names in
   the opponent panel, your own hand label, the "Waiting on X" / "X
   won" turn-status text, and every player-name mention in the game
   log (EventLog.tsx now builds each row as colored-name + plain-text
   segments instead of one flat string). Deliberately never the only
   signal for anything — the name text itself is always right there
   too — and the palette avoids the hues already carrying meaning
   elsewhere (gold/rose/sky-blue/red).

3. Enhancement: the legal-card hint (see the earlier delayed-glow
   work) now pulses with a couple percent of scale alongside the
   existing box-shadow brightening, so "ever so slightly" reads as an
   actual heartbeat rather than just a color shift that's easy to
   miss. Confirmed live that the computed transform genuinely
   oscillates over the animation cycle.

Investigated but NOT changed: a report that a lone unfinishable last
card (e.g. a Joker) "isn't allowed to play". Traced this in the
engine directly — it's working as designed, not a soft-lock: Ace/2/3/
8/J/Q/K/Joker can never be the literal winning card (traditional Kadi
rule, see finishable_ranks/ace_can_finish/joker_can_finish in
config.py), and a player stuck holding just one is always still free
to draw instead (_apply_draw permits drawing in AWAITING_MOVE
regardless of hand contents) — verified with a direct reproduction
against the engine. Flagged back to confirm this is the wanted
behavior before touching a core win-condition rule.

Verified: tsc/build/lint clean, backend pytest 129 passed (no backend
changes), and a live Playwright pass covering the forfeit-then-restart
button reappearing, matching colors for the same player id across both
clients, and the animated scale pulse on the legal-hint glow.
