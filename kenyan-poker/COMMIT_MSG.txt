Implements the requested visual/UX redesign brief. Reuses all existing
state, handlers, and API/WebSocket wiring as-is — no game logic, card
validation, turn logic, or multiplayer behavior changed. Backend
untouched (129 tests still pass).

Component decomposition (partial, per the brief's own "if
appropriate... do not unnecessarily rewrite" hedge):
- New OpponentPanel.tsx, CurrentCard.tsx, DrawButton.tsx (renamed
  from the old in-file ActionBar), each taking the same props/data
  Table.tsx already had — no new state, no hardcoded names/counts/
  cards, everything still comes from room.state.
- Deliberately did NOT extract TurnIndicator, GameHeader, QuitButton,
  or the individual Chat/Sound buttons into their own files: those
  are tightly interleaved with turn-status/pressure-pulse/aria-live
  logic that's already covered by tests and prior verification passes,
  and splitting them added regression risk without a real readability
  win. This — plus the loading-state note below — is the adapted
  portion of the brief; the rest was implemented as specified.

Decorative table elements: a subtle gold hairline divider with two
diamond caps under the top nav, and a soft radial glow behind the
current card/turn area — both aria-hidden, pointer-events: none, and
driven by two new low-alpha CSS tokens (--gold-decoration,
--panel-dark-* for future dark-panel work) rather than one-off
literals.

Responsive design: added a real tablet tier (768px) and a fleshed-out
mobile tier (480px, replacing the old single crude breakpoint). Mobile
switches the hand to horizontal scroll instead of shrinking cards
below a readable size. Document order (opponent panel → current card
→ turn state → primary action → hand → log) already matched the
brief's mobile priority list, so no reordering was needed.

Accessibility: PlayingCard's interactive button now carries
aria-pressed and a real aria-label built from the card's own rank/
suit data ("Queen of spades", "Joker, red", "...selected" when
picked) — never a hardcoded string. Added aria-live="polite" to the
turn-status region so turn/pressure changes are announced without
relying on color alone.

Explicitly skipped: a fake "loading" state on the Draw button. The
brief asks for one, but there's no real async request state in this
fire-and-forget WebSocket architecture to represent — fabricating one
would violate the brief's own "do not create fake functionality"
rule. Also skipped a full mechanical rgba-literal-to-token refactor of
pre-existing CSS (App.css/index.css) that was already visually correct
from prior turns' work this session — only new/touched rules use the
new tokens, to avoid a large-diff, high-regression-risk pass with no
visible benefit.

Everything else in the 20-section brief (deep emerald/gold palette,
opponent avatars with gold rings, gold "YOUR TURN" state, gold CTA
draw button, ivory cards with correct suit colors and Unicode suit
glyphs, "NAME (N CARDS)" hand label with info icon, structured game

Verified: tsc/build/lint clean, backend pytest 129 passed (no backend
changes), and a live Playwright pass covering desktop/tablet/mobile
